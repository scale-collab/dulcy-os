# Parent-first history collector: private candidate, off

This gathers past campaign leads and past final-list sheets for a parent-first
top-up. The existing saved rules decide which family and history belong to the
list. They keep the original split-family gate. This adds no support for an
unsplit family that the saved workflow rejects.

The five original source bodies match the latest local workflow capture from
November 11. Today’s published source has not been fetched again. The original
scope, family, Date.parse, identity and page rules run before each native bind.
No new date grammar replaces the source’s JavaScript check.

The new store accepts all three saved page operations: campaign leads, prior
sheet metadata and prior sheet rows. The older store accepted only campaign
pages. The new native entry derives family targets from raw current metadata,
keeps exact leases and receipts, and forwards each typed page to the unchanged
original native top-up kernel. That kernel owns page limits, identities, hashes,
the read/compare passes and changed-history stops.

Submit uses its existing native submission attempt. Check uses its own saved
job lease and event mapping. It does not borrow, renew, claim or requeue Submit.
The Check guard is owned by the existing journal owner; the runtime receives
only the new finite entry, with no raw table or source-schema access.

The loader verifies every candidate file before importing application code.
Worker/build/mode/executor are bound by trusted setup. A factory cannot replace
them. Accounts remain in the trusted capture port; only a safe reference crosses
the collector boundary. Importing the module starts no service or loop.

`prepareInstall` returns SQL for review only. It does not connect or run the SQL.
Its release is off, dependencies unreviewed, and no worker scope is registered.
It pins current stored dependency bodies and settings. It adds no broad source
grants or runtime table grants. It still needs a complete native dependency,
role/default-privilege and non-idle lifecycle proof before installation is ready.

This candidate is not joined to V18, selected, deployed or enabled. Portable
tests and SQL parsing do not prove native execution. In particular, the full
Submit and later Check cycles, native typed page receipts, races, crash/replay,
the Check event identity version, and independently enforced date ingress still
need direct proof. The source performs its Date.parse check, but this candidate
does not claim that arbitrary direct SQL calls enforce V8 date semantics.

The old core, all old helpers and jobs, old collectors and the working n8n
system stay unchanged. The separate 17-command paid API concerns a stopped
hybrid contact job after its source is reduced to DiscoLike. Normal hybrid
contact discovery already uses the ordinary worker; it is a separate path from
this history collector.
