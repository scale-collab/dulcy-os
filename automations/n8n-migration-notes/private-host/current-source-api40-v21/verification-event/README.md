# Private verification event link — off by default

The original saved verification validator and record/project planner stay unchanged. This adds one own-journal command around the original API28 open_verification_run facade. Each immutable (actual login, worker, event UUID) maps the exact source-validated request to its first native job identity. Lookup happens before any record read. Native admission and insertion of the mapping commit in the same transaction, protected by an event advisory lock. A lost bind reply can be resolved by lookup; concurrent matching requests return the first mapping. Changed record/action under the same event refuses. Later deliberate actions use a new UUID.

No frozen API28 file, source helper or business grant is rewritten. The additive trusted NOLOGIN entry owner owns only its new schema. Its old-API access is one facade EXECUTE and the exact release/principal metadata columns needed to honor current enrollment. It gets no raw business table rights or TEMP. Runtime gets only own-entry schema USAGE and one fixed function EXECUTE; no table rights. The old API28 facade still enforces all existing source/owner/layout/release/paid-work guards. Backend body, owner and definer settings are checked. All new scopes and the release start disabled.

prepare.mjs emits a reviewable fresh-schema plan only. It requires a separate manifest pin and exact database/operator/runtime/entry/backend roles. It does not connect, create roles, enroll scopes or enable anything. An existing schema, role drift, wrong target, raw rights or backend drift refuses. Installation is not production authorization or a complete cold base installer.

The new command is additive, not an SQL escape through API28's63-shape compiler. store.mjs captures its one parameterized template. Untrusted HTTP fields never supply source project, owner, worker, executor or admission mode.

This version supports the reviewed standard open path. The optional open_verification_handoff source branch is not among API28's63approved commands or reviewed backend closure. It is not silently enabled here; its dependency/scope review remains open. This fact does not shrink the full project goal.

Status returns the saved admission association, not current job completion. When separately configured with actual checked runtime ports, resume invokes existing source/check/legacy-adoption controllers; submission uses the existing leased global driver, and recovery continuation requires the original native proof. No listener, timer, durable host supervisor, provider transport or account is installed. Runtime joins and all modes still need native proof. No paid/provider/production work is authorized by this artifact.

Identifier checks keep the saved256-character limit using a character test and a separate length check. [PostgreSQL16 bounds stop at255](https://www.postgresql.org/docs/16/functions-matching.html#FUNCTIONS-POSIX-REGEXP).

Scopes use the full login/worker/record/spreadsheet key, matching the original backend. A new reviewed workbook for the same record can be added without changing an old scope. Existing events check their saved exact scope; absent lookup authorizes the record, while bind selects the exact source-planned sheet. An entry scope alone cannot grant backend verification authority.
