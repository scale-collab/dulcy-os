# Private contact-entry error status

This separate part is off by default. It wraps the verified API39/V20 host and
keeps its replies and failed-job history. It handles a known missing-company-
approval failure before any contact business job exists. It does not retry,
release, complete, delete or unlock that job, and it sends no notice or mail.

The database proves the exact saved own attempt, held intake attempt, immutable
request and captured false approval. A caller cannot supply an error, owner,
record or patch as authority. Unknown holds, later intakes and business jobs
are ineligible. The current saved lead-list error guard and protected-target
classifier produce the status fields. Native traces identify native work;
there is no invented n8n execution frame.

The writer looks up the current owner, freezes the exact source patch, checks
the record again, and claims one PATCH before sending it. A lost PATCH reply
does not allow another PATCH: it reads the saved fields back by both names and
IDs. The verified receipt reopens with no physical calls. A changed owner or
native proof stops further writes. Concurrent owner changes during the remote
request still need the wider race tests; this is not an atomic Airtable CAS.

Setup returns SQL only. It creates a new closed schema and grants the runtime
one typed function, with no raw-table rights. The no-login backend receives
only required metadata SELECT grants it lacks. Existing business rows, source
functions, core/host artifacts and older scopes are not changed.

The saved guard always marks an active contact queue Failed. It marks
Processing Status Failed only when that processing status was active. It keeps
the source message about the queue slot, while the native intake remains held.
The full display lifecycle, all other entry failures, registered contact V2,
family release, notices, safe approval-after-failure recovery and live producer
wiring remain separate work. No installation or live change is authorized here.

New API40/jobs4 adapter. A newer intake permits only a previously verified old
result with an unchanged sealed release. Its stored guard fields and source stay
unchanged; an unverified or drifted result still refuses. No live install.
